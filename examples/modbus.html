APPLICATION OVERVIEW

Modbus RTU with HRTOS

Modbus RTU is a widely used industrial communication protocol for exchanging data between controllers, sensors and automation equipment.

HRTOS provides an integrated Modbus RTU slave implementation that can be used as part of 8051-based embedded applications.

01

Serial Communication

Communicate with external Modbus masters through a serial interface.

  • UART communication
  • RTU frame reception
  • Serial data transmission
  • Frame processing
02

Modbus RTU Slave

Process Modbus RTU requests and provide register-based access to embedded application data.

  • Slave address handling
  • Function code processing
  • CRC validation
  • Protocol response generation
03

Register Management

Expose application variables through Modbus register interfaces for external access.

  • Coil operations
  • Holding registers
  • Input registers
  • Application data mapping
PROTOCOL FUNCTIONS

Supported Modbus Function Codes

The HRTOS Modbus RTU slave implementation supports common function codes for reading and writing application data.

01

FC01 - Read Coils

Read the status of multiple coils from the Modbus slave device.

02

FC03 - Read Holding Registers

Read one or more holding registers containing application data.

03

FC05 - Write Single Coil

Modify the state of an individual coil through a Modbus write request.

04

FC06 - Write Single Register

Write a single holding register to update application data.

05

FC10 - Write Multiple Registers

Write multiple holding registers within a single Modbus request.

COMMUNICATION ARCHITECTURE

Modbus RTU Processing Workflow

A typical Modbus RTU application receives serial frames, validates requests, processes function codes and returns corresponding responses.

1. Serial Data Reception

Receive incoming bytes from the UART interface and assemble the Modbus RTU request frame.

2. Frame Validation

Check the received frame, including slave address, frame length and CRC integrity.

3. Request Processing

Identify the requested function code and execute the corresponding register read or write operation.

4. Response Generation

Construct the appropriate Modbus RTU response frame and transmit it through the serial interface.

DATA INTERFACE

Register-Based Application Integration

Modbus registers provide a standardized interface between external industrial equipment and embedded application logic.

01

Coils

Represent discrete output states that can be read or modified by a Modbus master.

02

Discrete Inputs

Represent discrete input states provided by the embedded application.

03

Holding Registers

Provide access to readable and writable 16-bit application data.

04

Input Registers

Provide access to measurement and status data exposed by the embedded device.

HRTOS INTEGRATION

Industrial Communication with Real-Time Tasks

In an industrial embedded system, serial communication is often only one part of the overall application.

The microcontroller may also need to acquire sensor data, update outputs, manage system status and execute application control logic.

HRTOS allows these functions to be organized into independent tasks with defined priorities and scheduling behavior.

Modbus communication can be integrated with application tasks to exchange data between the embedded system and an external Modbus master.

This structure helps separate communication processing from application logic and makes the complete system easier to maintain and extend.

DEVELOPMENT CONSIDERATIONS

Designing Reliable Modbus Applications

Reliable Modbus RTU communication requires attention to serial timing, frame integrity and application data consistency.

Developers should configure UART parameters correctly, handle communication timeouts and validate received frames before processing requests.

Shared register data should also be managed carefully when multiple application tasks access or update the same resources.

HRTOS synchronization and task management facilities can help organize these operations within a structured embedded software architecture.
