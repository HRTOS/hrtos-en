EMBEDDED APPLICATION EXAMPLE

Infrared Remote Control

Interrupt-driven infrared reception and task-based event processing on 8051 microcontrollers.

This example demonstrates how HRTOS can organize infrared signal reception, protocol decoding and application-level event handling into structured tasks.

APPLICATION OVERVIEW

Infrared Signal Processing with HRTOS

Infrared remote control is a common embedded application that requires accurate signal timing, reliable data decoding and responsive event processing.

01

Signal Reception

Receive infrared signals through an infrared receiver module and detect changes in the input signal.

  • Infrared receiver interface
  • Signal edge detection
  • Timing measurement
  • Interrupt-based reception
02

NEC Protocol Decoding

Decode received infrared data according to the timing and frame structure of the NEC protocol.

  • Leader code detection
  • Address decoding
  • Command decoding
  • Frame validation
03

Task-Based Processing

Separate signal acquisition from application logic through independent HRTOS tasks.

  • Task scheduling
  • Event notification
  • Data processing
  • Application response
HARDWARE COMPONENTS

Hardware Requirements

A basic infrared remote control application can be constructed using a small number of common embedded hardware components.

8051 Microcontroller

An 8051 or MCS-51 compatible microcontroller running the HRTOS real-time operating system.

Infrared Receiver

A demodulating infrared receiver module, such as a 38 kHz receiver, for detecting remote control signals.

Infrared Remote

A compatible infrared remote control transmitting NEC-format command frames.

Optional Display

An LCD or OLED display can be integrated to present decoded addresses and command values.

SOFTWARE ARCHITECTURE

Application Processing Architecture

The application can separate low-level signal acquisition, protocol decoding and user-level processing into different software stages.

Hardware Interrupt

Detect infrared receiver signal transitions and capture timing information using the appropriate hardware interrupt or timer mechanism.

Signal Acquisition

Record signal timing information and make received data available for further processing.

Protocol Processing Task

Analyze the received timing sequence, decode NEC data frames and validate the resulting command information.

Application Task

Process decoded commands and perform corresponding application operations, such as controlling outputs or updating a display.

COMMUNICATION PROTOCOL

NEC Infrared Protocol

The NEC infrared protocol is widely used in consumer remote control applications. Its frame structure provides address and command information.

01

Leader Code

A leading pulse and space identify the beginning of a standard NEC transmission frame.

02

Address Field

The address field identifies the target device or remote control address.

03

Command Field

The command field carries the operation code associated with the pressed remote button.

04

Data Validation

Address and command complements can be checked to help validate received standard NEC frames.

HRTOS INTEGRATION

Why Use an RTOS for Infrared Applications?

A simple infrared remote control implementation can be developed using a traditional super-loop architecture.

However, when infrared reception becomes part of a larger embedded application, additional functions such as display updates, sensor acquisition and communication processing may need to operate concurrently.

HRTOS allows these functions to be organized into independent tasks while coordinating their execution through scheduling, synchronization and communication mechanisms.

This approach helps improve application structure, modularity and maintainability as system functionality grows.
