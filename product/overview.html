SYSTEM OVERVIEW

Inside the HRTOS System

HRTOS is organized as an integrated embedded software system for 8051 and MCS-51 microcontrollers. Its structure combines kernel services, system interfaces, hardware support and reusable application components.

System Architecture Technical Documentation
SYSTEM STRUCTURE

A Layered Embedded Software System

HRTOS separates operating system services, hardware interaction and application logic. This organization helps developers build structured firmware while keeping system components independently manageable.

01

Application Layer

Application tasks implement product functions such as data acquisition, display control, communication, monitoring and device management.

02

System Service Layer

System APIs provide task management, timing, synchronization, event handling and inter-task communication services.

03

Kernel Layer

The kernel manages task execution, scheduling decisions, task contexts and the core operating system mechanisms.

04

Hardware Support Layer

Hardware support provides the interfaces required to work with microcontroller peripherals and platform-specific resources.

05

Driver Layer

Peripheral and sensor drivers provide reusable interfaces for external devices and common embedded hardware.

06

Extension Layer

Optional software modules provide additional functions such as Modbus RTU, shell utilities and cooperative execution.

KERNEL SERVICES

Core Operating System Functions

The kernel provides the fundamental mechanisms required to coordinate multiple tasks and manage execution on resource-constrained 8051 microcontrollers.

Task Control

Tasks are managed as independent execution units. Developers can organize application functions according to their responsibilities and execution requirements.

Priority Scheduling

Priority-based scheduling coordinates task execution. Scheduling mechanisms support applications with different response and processing requirements.

Time Management

Timer-based services support delays, timeouts, periodic operations and time-related task coordination.

Interrupt Processing

Interrupt management supports interrupt-driven applications and coordination between interrupt events and task execution.

Synchronization

Semaphores, mutexes and event mechanisms help coordinate tasks and protect shared resources.

Message Communication

Message queues and mailboxes provide structured communication between independent application tasks.

Sensor Interfaces

Communication Interfaces

SOFTWARE EXTENSIONS

Additional Development Components

Beyond the kernel, HRTOS includes additional modules that support common embedded software development requirements.

01

Modbus RTU

A Modbus RTU slave implementation supports register-oriented communication and integration with industrial devices.

02

System Shell

Shell utilities provide command-based access to selected system information and debugging functions.

03

Cooperative Execution

The cooperative module provides an alternative execution approach for applications with different resource and scheduling requirements.

04

Application Examples

Example projects demonstrate the use of system APIs, drivers and extension modules in practical applications.

DEVELOPMENT WORKFLOW

A Structured Development Process

A typical HRTOS development project combines system configuration, application task design, hardware integration, compilation and on-device verification.

01. Configure

Select the target microcontroller, configure system resources and prepare the Keil C51 project.

02. Develop

Register application tasks and use system APIs to organize timing, synchronization and communication.

03. Integrate

Add hardware support, peripheral drivers and required extension modules to the application.

04. Verify

Compile the project, program the target device and evaluate application behavior through hardware testing.
