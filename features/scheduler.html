OVERVIEW

Task Scheduling in Embedded Systems

A real-time operating system coordinates multiple independent tasks while managing processor time and execution priorities.

Traditional single-loop embedded applications often combine hardware handling, data processing and communication in one execution flow.

As application complexity increases, maintaining this structure becomes difficult. Task scheduling provides a way to divide application functions into independent execution units.

HRTOS manages these tasks through a priority-based scheduling architecture designed specifically for the 8051 microcontroller family.

PRIORITY MODEL

Task Priority Organization

HRTOS uses priority levels to organize task execution and distinguish different scheduling requirements.

The HRTOS scheduling configuration supports multiple priority levels, allowing applications to assign execution importance according to functional requirements.

Priority Category Description
0 Idle Idle task
1 - 7 Normal Normal application tasks
8 High / Fast High-priority fast-task execution
9 - 10 Interrupt Interrupt execution priority levels

Interrupt priority levels are part of the system's interrupt execution model and should not be interpreted as ordinary application task priorities.

Actual task scheduling behavior depends on task state, priority and the configured scheduling rules.

FAST TASK ARCHITECTURE

A Dedicated Fast-Task Mechanism

HRTOS provides a separate execution mechanism for fast tasks, taking advantage of the register bank architecture available on 8051 microcontrollers.

Separate Execution Context

Normal tasks and fast tasks use different context management strategies.

The fast-task mechanism uses dedicated register bank resources, reducing the amount of context that must be saved and restored during fast-task switching.

Fast-Task Configuration

The standard HRTOS configuration provides two fast-task slots, identified separately from normal task IDs.

  • Normal task IDs: 0 - 15
  • Fast task IDs: 16 - 17
  • Fast-task capacity: 2 tasks
  • Dedicated fast-task context resources

Typical Applications

Fast tasks can be useful for frequently executed operations where reducing context-switch overhead is important.

Their use should be determined by actual application timing requirements and available hardware resources.

CONTEXT SWITCHING

Managing Task Execution Contexts

Context switching allows the processor to suspend one task and resume another while preserving the required execution state.

01

Current Task

The processor executes the currently selected task.

Scheduling Request
02

Context Management

The required execution context is preserved and the next task is selected.

Context Restore
03

Next Task

The processor resumes execution using the selected task's context.

Context management is particularly important on 8051 architectures, where register banks, internal RAM, external RAM and stack resources must be carefully coordinated.

HRTOS uses different context management strategies for normal and fast tasks.

TIME MANAGEMENT

Timer-Driven Scheduling

System timing provides the foundation for delay operations, time-based task management and periodic scheduling activities.

HRTOS uses Timer 0 as its system timing source in the documented standard configuration.

The system time base supports task delay operations and time-related scheduling services.

Timer configuration and clock settings determine the actual timing accuracy and system execution characteristics.

PERFORMANCE

Measured Context-Switch Performance

Context-switch performance has been evaluated on real 8051 hardware under documented test conditions.

On an STC12C5A60S2 running at 11.0592 MHz in 1T mode, HRTOS demonstrated the following measured task-switching times.

Switch Type Measured Time Test Condition
Normal Task 394.33 us Scheduling-bit triggered
Normal Task 550.33 us Time-slice scheduling
Fast Task 143.5 us Scheduling-bit triggered
Fast Task 229.5 us Time-slice scheduling

These values represent measured task-switching times under the specified test conditions. They are not universal guarantees for all 8051 devices or clock configurations.
