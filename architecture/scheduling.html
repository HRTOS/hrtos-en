SYSTEM ARCHITECTURE

Scheduling Architecture

A priority-based scheduling architecture designed for predictable task execution and efficient context switching on resource-constrained 8051 microcontrollers.

Scheduling Features Context Switch Performance
OVERVIEW

Scheduling Model

HRTOS combines priority-based task selection with cooperative scheduling requests and time-slice-based scheduling opportunities.

The scheduler determines which eligible task should execute next. It considers task priority, task state, scheduling requests, and the configured scheduling policy.

The scheduling architecture is designed around the constraints of the 8051 architecture, where CPU time, internal RAM, external RAM, and register resources must be carefully managed.

01

Priority-Based Selection

Task priority is used to determine execution precedence among eligible tasks.

02

Time-Slice Scheduling

Timer-driven scheduling opportunities support periodic task rotation according to the configured policy.

03

Fast Task Execution

A separate fast-task context mechanism provides a lower-overhead execution path for selected time-sensitive tasks.

PRIORITY MODEL

Task Priority Levels

HRTOS uses a configurable priority model to organize task execution and interrupt-related scheduling levels.

Priority Category Description
0 Idle Idle-level execution when no higher-priority eligible task requires CPU time.
1-7 Normal Priority levels used by normal tasks.
8 High / Fast High-priority execution level associated with fast-task scheduling.
9 Interrupt Interrupt-related scheduling level.
10 Nested Interrupt Scheduling level associated with nested interrupt execution.

Priority levels describe the kernel's execution hierarchy. They should not be interpreted as a guarantee that every interrupt or task transition can occur at any arbitrary point in execution. Interrupt nesting and scheduling API restrictions remain applicable.

NORMAL TASKS

Normal Task Scheduling

The normal task mechanism supports general application workloads and kernel services.

Task Capacity

The standard configuration supports up to 16 normal task contexts.

Priority Organization

Normal tasks use the configured priority levels to establish execution precedence.

Scheduling Requests

Kernel scheduling requests allow execution to move to another eligible task when scheduling conditions are met.

Time-Slice Support

Timer-driven scheduling provides an additional scheduling opportunity for normal task execution.

FAST TASKS

Fast Task Scheduling

A dedicated execution path for selected tasks that require reduced context-switch overhead.

In addition to normal tasks, HRTOS provides a fast-task mechanism with dedicated task contexts. This mechanism is intended for selected workloads where reducing task-switch overhead is important.

Fast tasks use a separate context organization and are limited in number. They are not simply normal tasks with a higher numeric priority; their execution mechanism is specifically designed for a different context-switch path.

02

Dedicated Contexts

The standard configuration provides two fast-task contexts.

05

Compact Context

Each fast-task context occupies 5 bytes in the documented standard memory layout.

TIME MANAGEMENT

Timer-Driven Scheduling

Timer0 provides the system timing foundation for periodic kernel time management.

HRTOS uses Timer0 as its system timer source. Timer-driven timing services maintain the kernel's time base and provide scheduling opportunities according to the configured system parameters.

Time-slice scheduling and task delay services are related to the system timing mechanism, but they serve different purposes. A delay request determines when a task becomes eligible again, while time-slice scheduling provides an opportunity to reconsider task execution.

Configuration Standard Value Purpose
OS_TIME_T0 10000 Timer0 timing configuration.
OS_TIME_ONCE_DEFAULT 5 Default one-time scheduling interval configuration.
Timer Source Timer0 System timing source.

These values describe the documented standard configuration. Actual timing behavior depends on the target MCU, oscillator frequency, timer setup, and system configuration.
