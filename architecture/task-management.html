Task Management

A structured task management mechanism for organizing concurrent application activities on 8051 and MCS-51 microcontrollers.

OVERVIEW

Task Management Model

HRTOS organizes application execution into independent task contexts managed by the kernel.

A task represents an execution unit within the operating system. Instead of placing all application logic inside a single main loop, developers can organize different functions into separate tasks.

Each task has an associated context and scheduling information. The kernel manages task execution together with timing services, synchronization mechanisms, and interrupt handling.

This structure makes it easier to separate application responsibilities, coordinate asynchronous events, and maintain predictable execution behavior.

01

Task Registration

Application tasks are registered with the kernel and assigned task identities and execution settings.

02

Context Management

Task execution contexts are maintained so that execution can resume after a task switch.

03

Execution Coordination

Tasks cooperate with scheduling, timing, synchronization, and communication services.

TASK TYPES

Normal Tasks and Fast Tasks

HRTOS provides two task-context categories for different execution requirements.

16

Normal Tasks

Normal tasks provide the general execution environment for application logic and kernel service interaction.

  • Task IDs: 0-15
  • Maximum contexts: 16
  • Context size: 13 bytes per task
  • Suitable for general application workloads
02

Fast Tasks

Fast tasks use a dedicated context mechanism to reduce task-switch overhead for selected time-sensitive workloads.

  • Task IDs: 16-17
  • Maximum contexts: 2
  • Context size: 5 bytes per task
  • Dedicated fast-task execution path

Normal and fast tasks are distinct context categories. Fast tasks should be reserved for workloads that benefit from their dedicated execution mechanism, rather than used as a general replacement for normal tasks.

TASK IDENTIFICATION

Task ID Organization

Task IDs provide a consistent way to identify task contexts within the standard configuration.

Task ID Range Task Category Capacity Context Size
0-15 Normal Task 16 13 bytes
16-17 Fast Task 2 5 bytes

The standard configuration provides 18 task contexts in total: 16 normal task contexts and 2 fast-task contexts.

Task IDs identify kernel-managed contexts. They should not be confused with application priority values or hardware interrupt vector numbers.

TASK REGISTRATION

Registering Application Tasks

Task registration connects application entry functions with kernel-managed task contexts.

During system initialization, application tasks are registered with the operating system. The registration process establishes the information required by the kernel to manage their execution.

Task configuration includes the task entry function and the relevant execution parameters. The exact API declaration and parameter order should follow the HRTOS V4.0.0 API documentation.

01

Define Task Function

Implement the application logic as a task entry function.

02

Register Task

Associate the task function with an available task context and configuration.

03

Initialize Services

Configure the required timing, synchronization, and communication resources.

04

Start Execution

Start the operating system and allow the scheduler to manage task execution.

TASK LIFECYCLE

Task Execution Lifecycle

Tasks interact with the kernel throughout their execution, waiting, and scheduling cycles.

01

Registered

The task has been configured and associated with a kernel-managed context.

02

Eligible for Execution

The task can participate in scheduling when its execution conditions are satisfied.

03

Running

The task currently owns the CPU and executes its application code.

04

Waiting

The task waits for a timing condition, synchronization event, or communication resource.

This lifecycle is a conceptual description of task execution. The actual internal state model and transition rules are defined by the HRTOS kernel implementation.

8051 IMPLEMENTATION

Task Contexts on 8051

Task management is closely related to the register and memory architecture of the MCS-51.

The 8051 architecture has limited internal RAM and a register-bank-based CPU organization. A task-switching implementation must account for the CPU state required to resume execution.

HRTOS uses separate context storage arrangements for normal tasks and fast tasks. This allows the kernel to balance task capacity and context-switch overhead within the memory constraints of the target device.

Context Category Number of Contexts Bytes per Context Total Storage
Normal Tasks 16 13 208 bytes
Fast Tasks 2 5 10 bytes
Total 18 ¡ª 218 bytes

These figures describe task-context storage in the documented standard memory layout. They do not represent the complete RAM consumption of the operating system or application.

CONFIGURATION

Task Management Parameters

The standard HRTOS configuration defines the available task-context capacity.

Parameter Value Description
OS_PROCESS_MAX 16 Maximum number of normal task contexts.
OS_FAST_TASK_MAX 2 Maximum number of fast-task contexts.
OS_SCHED_LEVEL_MAX 10 Configured scheduling-level limit.

The values shown above describe the standard HRTOS V4.x configuration. Custom builds may use different settings according to the target hardware and application requirements.
