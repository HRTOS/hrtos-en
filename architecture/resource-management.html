OVERVIEW

Managing Limited System Resources

Embedded systems often operate with strict limits on internal RAM, external RAM, and available processing capacity. HRTOS provides structured resource management to help applications coordinate tasks without relying on unrestricted dynamic allocation.

01

Defined Capacity

Resource capacities are configured according to the target system and its application requirements.

02

Task Coordination

Synchronization and communication mechanisms allow multiple tasks to coordinate access to shared resources.

03

Memory Awareness

Resource limits are designed with the memory constraints of 8051-class microcontrollers in mind.

CONFIGURATION

Configured Resource Capacity

HRTOS defines capacity limits for selected kernel resources. The following values describe the standard configuration of the HRTOS 4.x system.

Resource Standard Capacity Description
Normal Tasks 16 Normal task identifiers range from 0 to 15.
Fast Tasks 2 Dedicated fast task contexts for time-sensitive application processing.
Kernel Resources 6 Configured resource capacity in the standard system configuration.
Message Queues 3 Configured message queue capacity for inter-task communication.
Scheduler Levels 10 Configured scheduling priority levels.

These values describe configured system limits, not the amount of memory consumed by every application at runtime. Actual resource usage depends on the enabled kernel services, application configuration, and target hardware.

KERNEL SERVICES

Resource Types and Coordination

HRTOS provides several kernel services that help application tasks exchange information, synchronize execution, and coordinate access to shared resources.

Semaphores

Provide synchronization between tasks and help coordinate access to shared operations or resources.

Mutexes

Protect shared resources from conflicting concurrent access. HRTOS supports priority inheritance for mutex-based synchronization.

Events

Allow tasks to wait for event conditions and coordinate execution based on application events.

Message Queues

Provide buffered communication between tasks, allowing producers and consumers to operate independently.

Mailboxes

Support message-based communication between application tasks.

Unified Waiting

A unified waiting mechanism provides a consistent way for tasks to wait for supported synchronization and communication conditions.

ENGINEERING CONSIDERATIONS

Designing Within 8051 Constraints

Resource planning is an important part of embedded software engineering. HRTOS uses defined capacities to make system configuration easier to evaluate.

Plan Before Deployment

Estimate the number of tasks, synchronization objects, and communication channels required by the application.

Consider Memory Limits

Evaluate DATA, IDATA, and XDATA requirements together with the memory occupied by application variables and kernel contexts.

Validate Under Load

Test resource usage and task coordination under representative operating conditions, including concurrent events and communication activity.
