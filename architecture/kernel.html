HRTOS Kernel

OVERVIEW

A Kernel Designed for 8051 Systems

HRTOS provides an integrated kernel environment for building structured, task-oriented applications on resource-constrained 8051 microcontrollers.

The HRTOS kernel coordinates multiple application tasks and provides the services required for real-time application development. These include task management, priority-based scheduling, system timing, interrupt integration, synchronization, and inter-task communication.

Its implementation takes into account the characteristics of the MCS-51 architecture, including its register banks, memory spaces, interrupt mechanisms, and limited hardware resources.

Rather than relying on the assumptions of a larger processor architecture, HRTOS organizes its execution and resource management mechanisms around the practical constraints of 8051 devices.

KERNEL ORGANIZATION

Kernel Service Structure

The kernel is composed of cooperating services that manage execution, timing, and communication between application tasks.

01

Maintains task definitions, execution contexts, and task-related state.

TASK EXECUTION

Normal and Fast Task Execution

HRTOS provides two task categories with different execution context arrangements.

Normal tasks form the primary application execution environment. They use the standard task context mechanism and support the configured normal task capacity.

Fast tasks use a separate execution context arrangement that takes advantage of dedicated 8051 register-bank resources. This provides an alternative execution path for applications that require a different context-switching cost profile.

The two task categories are part of the same operating system environment, but they should not be assumed to have identical context management or resource requirements.

Task Category Task IDs Capacity Context Arrangement
Normal Tasks 0-15 16 Standard task contexts
Fast Tasks 16-17 2 Dedicated register-bank resources

EXECUTION CONTROL

Scheduling and Time Management

Task execution and time-related services are coordinated through the kernel's scheduling and timing mechanisms.

HRTOS uses priority-based scheduling to organize application task execution. Task priorities and execution states influence which task is selected by the scheduler.

A hardware timer provides the system timing source. In the standard HRTOS 4.x configuration, Timer0 is used as the system time base.

Time-related services allow applications to organize delays and waiting operations without relying exclusively on continuous polling loops.

Priority Levels

The standard configuration defines 10 scheduler levels through OS_SCHED_LEVEL_MAX.

Timer0 Time Base

Timer0 provides the configured system timing source.

Task Delays

Time-related kernel services support application delay and waiting behavior.

Scheduling Integration

Timing events are coordinated with task execution and kernel state.

8051 IMPLEMENTATION

Architecture-Aware Kernel Design

Kernel implementation is closely related to the native memory and execution model of the target microcontroller.

Register Banks

Execution context management considers the 8051 register-bank organization, including dedicated resources for fast tasks.

Memory Spaces

Kernel structures are organized with consideration for DATA, IDATA, XDATA, and CODE memory spaces.

Interrupt Mechanisms

Interrupt execution and nesting rules are designed around the target processor's interrupt architecture.

Resource Constraints

Task capacity, context storage, and system resources are configured for the requirements of 8051 systems.

KERNEL CONFIGURATION

Standard HRTOS 4.x Parameters

The following parameters describe the referenced standard kernel configuration.

Configuration Value Purpose
OS_PROCESS_MAX 16 Maximum number of normal tasks
OS_FAST_TASK_MAX 2 Maximum number of fast tasks
OS_SCHED_LEVEL_MAX 10 Configured scheduler levels
OS_TIME_T0 10000 Timer0 timing configuration
OS_TIME_ONCE_DEFAULT 5 Default time-related configuration

Parameter meanings and units should be interpreted according to the corresponding HRTOS configuration definitions and API documentation.
