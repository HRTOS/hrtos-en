PERFORMANCE

Timing Accuracy

Consistent timing is essential for real-time embedded applications. This page presents measured HRTOS delay behavior, millisecond-level timing results, and the role of the system time base on 8051 microcontrollers.

OVERVIEW

System Timing in HRTOS

HRTOS provides time-based services for task scheduling and application delays. These services allow tasks to wait for specified periods without requiring continuous busy waiting in application code.

System Time Base

Timer0 provides the periodic system timing reference used by the kernel in the documented reference configuration.

Task Delay

Tasks can enter a delayed state and resume execution when their configured waiting period has elapsed.

Time Measurement

Measured delay values provide practical information about timing behavior under a specific hardware and software setup.

The following measurements compare configured millisecond intervals with their recorded execution times on the STC12C5A60S2 platform.

Differences are calculated as measured time minus configured time. The values represent the recorded measurements under the stated test conditions.

TASK DELAY

os_delay() Measurements

The os_delay() interface allows a task to suspend its execution for a specified number of system time units. The following values are the recorded measurements for the tested configuration.

os_delay() Argument Measured Time Approximate Duration
os_delay(1) 12.572 ms 12.572 ms
os_delay(5) 56.6729 ms 56.673 ms
os_delay(10) 111.80 ms 111.800 ms
os_delay(100) 1.104 s 1104 ms

The os_delay() measurements are presented separately from the millisecond interval measurements above. They describe the observed behavior of this API under the tested configuration and should not be assumed to have a one-to-one numerical relationship with the configured millisecond intervals.

SYSTEM TIME BASE

Timer0-Based Timing

HRTOS uses Timer0 as the system time base in the documented reference configuration. Periodic timer activity provides the timing reference required by kernel time services.

Periodic Time Reference

The system timer generates periodic timing events. These events allow the kernel to update time-related state and manage tasks that are waiting for a specified period.

Task Delay and Scheduling

When a task requests a delay, it is placed into a waiting state according to the kernel's time-management mechanism. Other eligible tasks can execute while the delayed task is waiting.

Hardware-Dependent Timing

Actual timing behavior depends on the microcontroller clock, timer configuration, timer interrupt processing, and software execution overhead. The selected system time base is therefore an important part of the measurement environment.

TIMING FACTORS

Factors Affecting Timing Behavior

Configured time intervals and observed execution times may differ because of several hardware and software factors.

Clock Frequency

The MCU clock determines the timing resolution of hardware timer operation and instruction execution.

Timer Configuration

Timer reload values, timer mode, and interrupt frequency influence the system time reference.

Interrupt Processing

Interrupt entry, execution, and return contribute to the total processing overhead associated with timekeeping.

Scheduling Activity

Task scheduling and context switching affect when a delayed task actually resumes execution.

ENGINEERING NOTES

Interpreting Timing Results

Timing measurements should be evaluated according to the behavior being measured and the requirements of the target application.

Configured Interval vs. Actual Execution Time

A configured delay represents a requested waiting period. The actual time before a task resumes can also depend on timer resolution, scheduling activity, and other system execution overhead.

Time Base vs. Application Response

System time-base accuracy and application-level response time are different properties. A periodic timer can provide a consistent time reference, while the time at which an application task executes also depends on scheduling and system load.

Measurement Scope

The published results describe the tested configuration. They are not universal guarantees for all 8051-compatible devices, clock frequencies, compiler settings, or application workloads.
