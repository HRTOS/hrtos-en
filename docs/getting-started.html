Getting Started with HRTOS

Start building real-time embedded applications with HRTOS on 8051 and MCS-51 microcontrollers.

This guide introduces the essential development workflow, from preparing your toolchain and configuring the system to creating tasks and running your first application.

Installation Guide Download HRTOS
Introduction

Your First HRTOS Project

Understand the basic workflow before integrating HRTOS into an embedded application.

HRTOS provides a structured runtime environment for applications built on 8051-family microcontrollers. Instead of implementing all application behavior inside a single main loop, developers can organize their programs into independent tasks.

Each task can perform a specific function, such as sensor acquisition, communication, display updates, or background processing. HRTOS manages task execution and provides synchronization mechanisms for coordinating these activities.

A typical development process includes the following stages:

01

Prepare

Select a compatible 8051 microcontroller and prepare the Keil C51 development environment.

02

Configure

Review system configuration options, memory requirements, and enabled modules.

03

Integrate

Add the required HRTOS libraries and interface files to your application project.

04

Develop

Initialize the system, register tasks, and implement application functions.

Prerequisites

What You Need

Prepare the hardware and software resources required for an HRTOS development project.

01

8051 Microcontroller

Choose an 8051 or MCS-51 compatible microcontroller that meets the system's memory and peripheral requirements.

  • Compatible 8051/MCS-51 architecture
  • Sufficient CODE memory
  • Sufficient XDATA memory
  • Suitable timer and interrupt resources
02

Keil C51

HRTOS V4.0.0 is designed for the Keil C51 development environment.

  • Keil C51 compiler
  • 8051 target configuration
  • Project and linker configuration
  • Device-specific header files
03

HRTOS Package

Prepare the HRTOS distribution and the files required by your selected system configuration.

  • HRTOS library files
  • Public interface headers
  • Configuration files
  • Documentation and examples
04

Development Hardware

A development board or target circuit is recommended for testing the system on real hardware.

  • 8051 development board
  • Power supply and programming interface
  • Serial communication interface
  • Optional debugging equipment
Hardware Requirements

Check System Resources

Verify that the target microcontroller can accommodate the selected HRTOS configuration.

Before creating a project, check the memory capacity of the target device. The full HRTOS configuration has the following baseline requirements:

8 KB+

CODE Memory

1 KB+

XDATA Memory

8051

CPU Architecture

Keil C51

Development Toolchain

These values are baseline requirements for the full system configuration. Actual resource consumption depends on the enabled modules, task configuration, and application code.

Devices with limited external data memory should be evaluated carefully. A cooperative configuration may be more appropriate for some resource-constrained applications.

For supported hardware information, see Hardware Platforms.

Step 01

Prepare the Development Environment

Set up the compiler and organize the project before integrating HRTOS.

1. Install and configure Keil C51

Install a compatible Keil C51 development environment and make sure that the compiler can build a basic 8051 application.

Select the correct target device and verify the memory model and compiler settings required by your hardware.

2. Prepare the HRTOS files

Extract the HRTOS distribution and locate the library files, public headers, configuration files, and example projects.

Keep the original package structure available for reference during integration.

3. Create an application project

Create a new Keil C51 project for your target microcontroller.

Add the application source files and configure the required include paths and library search paths.

4. Review the system configuration

Check the HRTOS configuration options and select the modules and resource settings required by your application.

Avoid enabling unnecessary modules during the initial bring-up process.

For detailed integration instructions, see the Installation Guide.

Step 02

Integrate HRTOS into Your Project

Add the required system components and prepare the application entry point.

HRTOS integration involves connecting the operating system library and its public interfaces to the application project.

The following items should be checked during integration:

01

Include Paths

Make sure that the compiler can locate the HRTOS public header files and required device headers.

02

Library Linking

Add the appropriate HRTOS library files to the project and verify the linker configuration.

03

System Configuration

Review the system configuration and make sure that the selected settings match the target hardware.

04

Application Entry

Prepare the application startup code according to the initialization sequence documented by HRTOS.

Use the official examples as the reference for the exact initialization sequence and interface usage. Avoid assuming that configuration details are identical across different HRTOS versions.

Step 03

Create Your First Tasks

Organize application functionality into independent tasks managed by HRTOS.

A task is an independent unit of application execution. In a typical embedded project, different tasks can be assigned to different functions.

01

Sensor Task

Periodically acquire sensor data and update application variables.

02

Communication Task

Process serial communication, protocol messages, or external device requests.

03

Display Task

Update display information and present application status.

04

Background Task

Handle non-critical processing and periodic maintenance work.

Task Design Guidelines

  • Keep each task focused on a clear responsibility.
  • Choose priorities according to response-time requirements.
  • Use system synchronization mechanisms for shared resources.
  • Avoid unnecessary busy-wait loops.
  • Consider task execution time and stack requirements.

For more information, see Task Scheduling and API Reference.

Step 04

Coordinate Tasks and Resources

Use synchronization and communication mechanisms to build reliable multi-task applications.

01

Semaphores

Coordinate task execution and manage access to shared system resources.

02

Mutexes

Protect shared resources and support priority inheritance when tasks compete for the same resource.

03

Events

Allow tasks to wait for and respond to application events.

04

Message Queues

Exchange data between tasks through structured message communication.

Select the appropriate synchronization mechanism based on the data flow and resource-sharing requirements of your application.

Avoid sharing mutable data between tasks without a clearly defined synchronization strategy.

Step 05

Build and Run the Application

Compile the project, program the target microcontroller, and verify system startup.

1. Compile the project

Build the application in Keil C51 and review the compiler and linker output.

Resolve missing symbols, incorrect include paths, memory allocation problems, and configuration conflicts.

2. Check memory usage

Review the generated memory usage report and confirm that the application fits within the target device's available CODE and data memory.

3. Program the microcontroller

Download the generated program to the target device using the appropriate programming tool.

Verify power supply, clock configuration, reset behavior, and basic hardware connections.

4. Verify system operation

Check that the system initializes correctly and that registered tasks execute as expected.

Use serial output, GPIO signals, debugging tools, or other suitable methods to observe system behavior.

Validation

Verify Your First Application

Confirm the essential operating system behavior before expanding the application.

A successful compilation does not necessarily mean that the complete application behaves correctly. Initial validation should focus on the basic system functions.

01

System Startup

Confirm that initialization completes and the application reaches its expected startup state.

02

Task Execution

Verify that registered tasks execute and that their priorities produce the expected scheduling behavior.

03

Timing Behavior

Measure periodic task behavior, interrupt response, and relevant application timing.

04

Resource Stability

Check memory usage, stack behavior, shared-resource access, and long-running system stability.

For measured performance information, see the Performance section.
