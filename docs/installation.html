HRTOS Installation Guide

Prepare your Keil C51 development environment and integrate HRTOS into an 8051 embedded project.

This guide walks through the essential setup process, including hardware requirements, project configuration, library integration, compilation, and deployment.

Requirements

System Requirements

Make sure that your development environment and target hardware meet the basic requirements.

01

Target Architecture

HRTOS is designed for the 8051 and MCS-51 microcontroller architecture.

  • 8051/MCS-51 compatible processor
  • Compatible compiler environment
  • Suitable timer and interrupt resources
02

Development Toolchain

HRTOS V4.0.0 is designed for the Keil C51 development environment.

  • Keil C51 compiler
  • 8051 device configuration
  • Project and linker configuration
03

Memory Resources

The full HRTOS configuration has the following baseline memory requirements.

  • CODE memory: 8 KB or more
  • XDATA memory: 1 KB or more
04

Development Hardware

A compatible development board or target circuit is recommended for system verification.

  • Stable power supply
  • Programming interface
  • Optional serial debugging interface

The memory figures are baseline requirements for the full configuration. Actual resource usage depends on enabled modules, application code, and task settings.

For more information, visit Hardware Platforms.

Step 01

Obtain the HRTOS Distribution

Start with the official HRTOS package and review the available resources.

Download the Package

Obtain the HRTOS distribution from the official download page.

Select the release that matches your intended development environment and target platform.

Visit Download Page

Review the Package Contents

After extracting the distribution, identify the files required by your project.

  • HRTOS library files
  • Public interface header files
  • System configuration resources
  • Documentation and API references
  • Example applications and extensions

The exact package organization may vary between releases. Refer to the documentation included with the selected version.

Keep the Original Package

Keep an unchanged copy of the original distribution. Create a separate working directory for project integration and application-specific modifications.

This makes it easier to compare files and restore the original configuration when troubleshooting.

Step 02

Configure Keil C51

Prepare the compiler and create a project for your target microcontroller.

1. Select the Target Device

Create a new Keil C51 project and select the microcontroller that matches your hardware.

Confirm that the selected device definition and compiler settings are appropriate for the target.

2. Review Compiler Settings

Check the compiler configuration, memory model, optimization settings, and other project options required by the HRTOS distribution.

Keep the settings consistent with the official examples whenever possible.

3. Configure Include Paths

Add the directories containing the required HRTOS public headers and device-specific header files.

Verify that the compiler can locate every required header during the build process.

4. Configure the Linker

Review the project library settings and make sure that the required HRTOS library files are included in the build.

Check memory allocation and linker output for conflicts or insufficient target resources.

Step 03

Integrate HRTOS Libraries

Connect the HRTOS library and public interfaces to your application project.

HRTOS integration should follow the organization and configuration of the selected distribution. Use the provided project examples as the primary reference for the exact files and integration sequence.

01

Library Files

Add the appropriate HRTOS library files to the project and verify that the linker can resolve the required system symbols.

02

Public Headers

Include the public interface headers required by the application and the enabled system modules.

03

Configuration

Review the HRTOS configuration and confirm that the selected options match the target device.

04

Application Sources

Add the application source files and any required hardware driver or extension modules.

Do not mix files from different HRTOS releases without checking compatibility. Keep library files, headers, and configuration resources from the same release wherever possible.

Step 04

Configure the Operating System

Select the system resources and modules required by your application.

Task Configuration

Review the task capacity and priority configuration. Allocate enough task resources for the application while keeping the system within the target's memory limits.

Timing Configuration

Configure the system timing source according to the target clock and timer resources.

Verify the timing configuration on actual hardware, especially when the application has strict timing requirements.

Module Selection

Enable the system services and extensions required by the project. These may include synchronization, communication, Shell, debugging, or hardware-related components.

Start with the minimum required configuration and add additional modules as the application develops.

Memory Configuration

Review the memory model and resource allocation. Make sure that system data, task contexts, application variables, and stack usage fit within the available memory.

Step 05

Compile and Link the Project

Build the application and resolve any integration or configuration problems.

Run the Build Process

Compile the application using the configured Keil C51 project. Review the build output rather than relying only on the final success or failure message.

Check Compiler Messages

Review warnings and errors related to missing headers, incorrect declarations, incompatible data types, and source configuration.

Check Linker Output

Verify that all required symbols are resolved and that the generated program fits within the target memory layout.

Pay particular attention to CODE and XDATA usage when integrating additional application modules.

Review the Generated Program

Confirm that the output file corresponds to the selected target device and the intended HRTOS configuration.

Step 06

Deploy to Target Hardware

Program the microcontroller and verify the basic operation of the system.

1. Check Hardware Connections

Verify the power supply, clock source, reset circuit, programming interface, and required peripheral connections.

2. Program the Device

Use the appropriate programming utility to download the generated application to the target microcontroller.

3. Verify System Startup

Power on or reset the target device. Confirm that the application reaches its expected initialization state.

4. Observe Task Behavior

Use serial output, GPIO signals, debugging tools, or other suitable methods to verify that application tasks are running correctly.

Troubleshooting

Common Installation Problems

Check these items when the project cannot be compiled or started correctly.

Header Files Cannot Be Found

Check the compiler include paths and verify that the required HRTOS header files are present in the selected distribution.

Unresolved External Symbols

Verify that the correct HRTOS library files are included and that the headers and libraries belong to compatible releases.

CODE or XDATA Memory Overflow

Review the target memory capacity, enabled modules, application variables, and linker configuration.

Consider whether the selected system configuration is suitable for the target device.

The Application Does Not Start

Review the initialization sequence, timer configuration, hardware clock, reset behavior, and target-specific settings.

Runtime Behavior Is Unexpected

Check task registration, priorities, synchronization conditions, interrupt handling, and timing configuration.

Test the application incrementally and use the official examples as a reference.

For more answers, see the Frequently Asked Questions.

Best Practices

Recommended Integration Strategy

A gradual integration process makes development and troubleshooting easier.

01

Start with a Minimal Project

First verify the basic HRTOS initialization and task execution before adding complex application logic.

02

Add Modules Incrementally

Integrate communication, synchronization, drivers, and other extensions one step at a time.

03

Measure on Real Hardware

Verify timing behavior, memory consumption, and interrupt response on the actual target device.

04

Keep the Project Maintainable

Separate application logic, hardware drivers, and system configuration to make future development easier.
